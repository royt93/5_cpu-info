# Epic 3 — Feature mới (gap vs competitor)

> `doc/quick_win.md` đã cover: Camera, Display/refresh rate, Media codec, DRM/Widevine, Export report, Network info, Battery health, Floating overlay. **Không lặp lại các mục đó** — epic này chỉ chứa gap MỚI phát hiện qua review, so với competitor CPU-Z, AIDA64, Device Info HW, CPU Monitor.

| # | Feature | Mô tả | Effort | Giá trị | Nguồn |

| ✅F01 | Realtime dashboard có lịch sử | **Đã xong (2026-09-01)** — tab mới `feat/infor/dashboard` (`FrmDashboard`/`VMDashboard`), vị trí 15 trong ViewPager Hardware. 3 biểu đồ line chart: CPU utilization trung bình (%, tính từ `current/max` mỗi core qua `ObservableCpuData`), RAM used (%, qua `ObservableRamData`), battery temp (°C, qua `ObservableTemperatureData`). Rolling buffer 15 phút (`HistoryBuffer`, evict theo tuổi) — chart tự động chứa cả 3 mốc 1/5/15 phút, **không làm UI toggle riêng**: dựa vào pinch-zoom/pan built-in của thư viện chart thay vì tự dựng window picker (đơn giản hoá có chủ đích, xem library choice bên dưới). **Library**: `MPAndroidChart` (JitPack, Java thuần) thay vì Vico — Vico là Compose-only, build bằng Kotlin hiện đại (rủi ro đúng loại xung đột metadata mà `build.gradle.kts` `force()` block đã ghi chú; đã research trước khi chọn). Verify: `HistoryBufferTest` (4 test) + `VMDashboardTest` (5 test) unit, `assembleDevDebug`/`lintDevDebug` xanh với dependency mới. **Không có instrumented test cho tab này** — điều hướng vào tab kích hoạt lỗi teardown ở tầng test harness (`ActivityScenario` "Cannot run onActivity since Activity has been destroyed already"), xác nhận qua logcat KHÔNG phải app crash thật (process exit code 0, không có FATAL EXCEPTION). **Cập nhật khi làm F06**: ban đầu nghi do `VMDashboard` poll liên tục mỗi giây khiến `composeRule.waitForIdle()` không "settle", nhưng F06 (event-driven, không poll) gặp lỗi harness y hệt → nguyên nhân thật là môi trường test harness/device (xác nhận thêm qua 2 device khác nhau cho 2 lỗi harness khác nhau khi làm F06), không phải đặc thù polling của F01 — quyết định bỏ test vẫn đúng, chỉ sửa lại phần chẩn đoán | L (2-3d) | 🌟🌟🌟 | Codex |

| ✅F06 | Storage/CPU benchmark nhẹ có baseline | **Đã xong (2026-09-01)** — package mới `feat/storagebench` (`FrmStorageBench`/`VMStorageBench`), vị trí 16 trong ViewPager Hardware, theo đúng khuôn mẫu U02 Throttle (`ThrottleFingerprint`/`ThrottleTestRunner`/`ThrottleResultPrefs`) đã có sẵn: pure-math object (`StorageBenchmark`) + runner I/O thật (`StorageBenchmarkRunner`) + prefs lưu kết quả trước đó để so sánh (`StorageBenchResultPrefs`, không phải bảng baseline chipset cứng — dùng chung khái niệm "before/after" như Throttle). 5 phase: ghi/đọc tuần tự 32MB, ghi/đọc ngẫu nhiên 500×4KB, băm SHA-256 1 giây — toàn bộ chạy trong `context.cacheDir`, xoá file tạm ở `finally` dù kết thúc ở phase nào. **An toàn nhiệt**: tái dùng đúng ngưỡng 43°C của `ThrottleFingerprint.SAFETY_ABORT_TEMP_C` (không tự đặt ngưỡng mới), check trước khi bắt đầu + check lại giữa chừng sau 2 phase tuần tự — không cần hard duration cap hay cooldown timer bắt buộc như Throttle vì tổng thời gian test chỉ ~10-15s (ngắn hơn nhiều so với 30s multi-core burn của U02). **Không tự dựng bảng baseline theo chipset** (không có dữ liệu thật để so sánh) — dùng lại đúng pattern "so kết quả với lần chạy trước" đã chứng minh hợp lý ở Throttle. Verify: `StorageBenchmarkTest` (5 test) unit, `assembleDevDebug`/`lintDevDebug` xanh. **Không có instrumented test** — cùng lý do F01: lỗi harness `ActivityScenario` "Cannot run onActivity..." tái hiện y hệt dù VM này KHÔNG poll liên tục (event-driven, khác hẳn F01) — xác nhận qua logcat trên **2 device khác nhau** cho 2 lỗi harness khác nhau (TECNO: teardown NPE; Pixel 7 Pro: `NoSuchMethodException InputManager.getInstance`, lỗi tương thích Espresso/API version đã biết) → chắc chắn không phải bug code, không phải lỗi app crash | M (1d) | 🌟🌟 | Codex + Claude CLI |

| F08 | Vulkan/OpenGL ES chi tiết hơn | Full extension list, Vulkan API level, compute shader support (mở rộng tab GPU sau khi fix bug B04) | S (0.5d) | 🌟 | Claude CLI |
| F09 | CPU Cluster Topology (Prime/Performance/Efficiency) | Hiện app liệt kê phẳng Core 0-N, không phân biệt nhân nào Cortex-X (Prime) / Cortex-A (Perf/Eff). Dùng `libcpuinfo` nhóm core theo cluster, hiển thị microarchitecture + xung min/max từng cụm — đúng cách CPU-Z/Device Info HW làm. **Trùng hướng với U06 (Epic 4)** — nên làm chung 1 task, U06 là bản mở rộng sâu hơn (thêm cache hierarchy) | M (1d) | 🌟🌟🌟 | Gemini CLI |
| F10 | NPU/AI Capability Detection | Phát hiện NPU/TPU (Hexagon/APU/Tensor), NNAPI HAL version, tập lệnh tăng tốc ma trận (`i8mm`, dot product, `bf16`, SVE/SVE2) — `libcpuinfo` đã có sẵn cờ này, chưa khai thác. Xu hướng on-device AI 2025-2026, chưa app system-info nào trong phân khúc có. **Là nền tảng cho U12 (Epic 4)** | M (1d) | 🌟🌟🌟 | Gemini CLI |
| ✅F11 | Audio Hardware capabilities | **Đã xong (Sprint 16, 2026-08-30)** — tab `feat/infor/audio` mới: native sample rate/buffer, low-latency/pro-audio feature flags, mic count, spatial audio (Spatializer API 32+), per-output-device channel counts/sample rates/encodings (PCM/AC-3/E-AC-3/DTS/Dolby Atmos JOC/AC-4). Scope hẹp hơn mô tả gốc: **bỏ BT codec (LDAC/aptX)** — cần `BLUETOOTH_CONNECT` runtime permission + thiết bị A2DP đã ghép nối, không phù hợp tab read-only 0-permission như batch quick-win trước. Zero permission mới. Xóa hẳn code ALSA `/proc/asound` chết trong `VMHardwareInfo` (đã xác nhận SELinux chặn từ lâu — `getSoundCardNumber()` luôn fallback về "1", `tryToGetSoundCardId`/`tryToGetAlsa` luôn fail âm thầm, hiển thị "1 sound card / Unknown id" giả) — tab Hardware hết mục "Sound card" gây hiểu nhầm, dữ liệu thật giờ ở tab Audio mới | S (0.5d) | 🌟🌟 | Gemini CLI |
